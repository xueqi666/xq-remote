# 构建校验、环境选择与部署目录切换

## 问题原因

旧流程使用 `mkdir -p` 后直接执行 `tar -xzf`。解压只会新增或覆盖同名文件，不会删除新包中不存在的文件，因此上次构建的 JS、CSS 和其他旧文件会残留。

## 当前流程

1. 按命令行参数、`NODE_CONFIG_ENV`、`NODE_ENV` 的顺序选择环境。CLI 参数同时覆盖两个环境变量，防止显示环境与实际加载环境不一致。
2. 从 node-config 实际加载来源中精确匹配环境文件名。例如 `prod` 必须有 `prod.json` 或其他 node-config 支持格式的同名文件，不能匹配 `production.json`，也不能仅依赖默认配置。格式错误同样终止；输出实际加载的所有配置来源，不打印配置值或密码。
3. 检查本地构建目录和 `requiredFiles`。检查远程路径边界，再压缩构建产物。
4. 连接 SSH 后先创建远程父目录和上传包父目录，检查上传目录可写、可进入。此步骤成功后才启动 SFTP，失败时不上传、不修改线上版本。
5. 使用 `tar -tzf` 检查上传包，并在目标目录的同级位置用 `mktemp -d` 创建 `.xq-remote-XXXXXX` 临时目录。
6. 解压到临时目录的 `new` 子目录，验证含有非空普通文件、不含符号链接，逐个检查 `requiredFiles`。权限仍沿用原来的 `777` 设置，在切换前完成。
7. 旧版本存在时将其重命名为临时目录中的 `previous`，再将 `new` 重命名为线上目录。首次部署直接安装新目录。
8. 成功后删除临时目录及其中的旧版本，再删除上传包并输出部署完成。旧资源及隐藏文件不会残留在新版本中。

所有远程命令在 `set -e` 下顺序执行。配置、构建校验、压缩、目录准备、上传、SSH 执行及远程命令失败均返回非零退出码，供 CI/CD 判断失败。

## 构建产物和环境配置

`localDir` 不能留空，必须存在且为目录，不能是项目根目录或其祖先。检查使用真实路径，避免符号链接别名绕过根目录检查。递归检查至少存在一个有内容的普通文件；仅有空目录或零字节文件不算有效构建。构建内容中的符号链接及特殊文件不支持，需先生成完整的实际文件。

`requiredFiles` 为可选相对文件路径数组，默认为 `[]`。路径不能是绝对路径或越出构建目录，每个指定文件必须是非空普通文件；配置文件夹名称不能代替文件。Windows 反斜杠会统一为包内使用的正斜杠。本地与实际解压内容均进行检查，防止可正常读取但为空或不完整的 tar 包替换线上版本。

未指定环境时保留 node-config 默认合并规则，并要求加载到 `default` 配置；node-config 仍可能合并 `development`、主机名和 `local` 等配置。显式指定的环境必须有同名配置文件，连 `development` 也不豁免。单次部署支持一个环境名，支持 `NODE_CONFIG_DIR`；只设置 `NODE_CONFIG` 而不提供对应配置文件不能绕过环境检查。需要部署哪个环境时建议显式传入环境名，并查看实际来源日志。

## 配置示例和删除范围

```json
{
  "localDir": "dist",
  "requiredFiles": ["index.html"],
  "remoteDir": "/var/www/my-app",
  "remoteExtractedDir": "dist",
  "remoteTarFileName": "dist.tar.gz"
}
```

这组配置替换 `/var/www/my-app/dist`，上传包为 `/var/www/my-app/dist.tar.gz`。解压目录必须严格位于 `remoteDir` 内，不能为父目录本身或通过 `..` 越界；上传包也必须位于父目录内，且不能与解压目录重叠。临时目录位于目标目录同级，使普通目录部署可通过同一文件系统内的重命名完成切换。

路径检查按 POSIX 路径层级进行，部署父目录和中间目录应为可信目录，避免通过符号链接将路径指向其他位置。线上目标本身不能是符号链接或普通文件。远程路径使用 shell 单参数引用，支持空格、单引号等字符。工具按 Linux 部署设计，需要 `tar`、`find`、`mktemp`、`chmod`、`rm` 及支持 `-T` 的 `mv`。

## 失败恢复和限制

| 失败阶段 | 线上版本与处理 |
| --- | --- |
| 本地检查、压缩、目录准备、上传 | 不修改线上版本，返回错误。 |
| 包检查、解压、内容校验、权限设置 | 旧版本仍在原路径，清理本次临时解压目录。 |
| 移动旧目录失败 | 保留原目录，清理临时目录。 |
| 旧目录已移动，但安装新目录失败 | 退出陷阱尝试把 `previous` 恢复到原路径。 |
| 恢复失败或恢复时目标被其他进程占用 | 保留临时目录及备份，打印备份路径，返回错误，禁止清理旧版本备份。 |
| 新版本已经安装，旧版本或上传包清理失败 | 新版本保持在线，返回错误并保留未能清理的内容，不回滚已完成的切换。 |

退出陷阱处理正常错误退出及 HUP、INT、TERM。SIGKILL、服务器断电或底层文件系统故障无法保证自动恢复，需根据保留目录人工检查。失败时上传包保留供排查。恢复需要目标路径没有被其他进程占用；本次未增加并发部署锁，同一目标应串行部署。

这不是零停机发布：移动旧版本和安装新版本之间仍有短暂路径缺失窗口，但解压和验证时间已移到切换之前。旧版本里的运行期上传文件等持久化数据应放在外部。需要预留新包、完整解压结果与旧版本同时存在所需的磁盘空间。本地 tar 包仍保留在调用项目中。

## Node.js 14 兼容性

最低支持版本保持为 Node.js 14.0.0。部署代码采用 CommonJS，使用 Node 14 支持的 `fs.realpathSync`、`fs.readdirSync({ withFileTypes: true })`、`fs.statSync`、`child_process.execFileSync` 等接口，不依赖 `node:test`、全局 `fetch`、`fs.rmSync` 或更新版本专有的 API。

当前安装的 `config 3.3.12`、`cross-env 7.0.3`、`ssh2 1.17.0` 声明的最低 Node 版本均低于 14。升级依赖时需继续检查它们及传递依赖的 Node 版本要求。

移除测试前已在 Node.js 14.18.0 下完成语法检查、依赖加载及全部原有回归用例，覆盖构建与环境校验、首次部署、连续替换、失败中止和恢复。验证仅使用本地临时目录与模拟 SSH，未连接真实服务器。

测试文件及 `npm test` 命令已按项目要求移除。日常可使用 Node 14 执行以下语法检查，检查本身不会连接服务器：

```bash
node --check remote.js
node --check deployment-config.js
node --check remote-commands.js
```

Node 运行时只需安装在执行部署脚本的机器上；远程服务器执行的是生成的 shell 命令，所需工具见前文。
