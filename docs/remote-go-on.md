# 部署后的 remoteGoOn 命令

## 配置与触发时机

`remoteGoOn` 是可选的命令字符串数组，缺省值为 `[]`，可以在 `config/default.json` 或环境专属配置中设置。环境配置的数组按 node-config 规则整体覆盖默认数组，而不是追加。设为 `[]` 可以禁用默认配置的后续命令。

```json
{
  "remoteGoOn": [
    "docker exec app-nginx sh -c \"rm -rf /usr/share/nginx/html/*\"",
    "docker cp /var/www/my-app/dist/. app-nginx:/usr/share/nginx/html/"
  ]
}
```

这里的示例假设新版本已部署到 `/var/www/my-app/dist`，先等待容器清理命令结束，再将新文件复制到容器。实际命令中的源目录应与部署后的解压目录对应。

清单必须为数组，每一项必须为非空字符串，不能含 NUL。Windows CRLF 换行会统一为 LF，引号、空格和其他 shell 语法保持原意。错误配置在压缩、上传和连接服务器之前终止。

触发顺序为：本地校验和压缩 → 远程目录准备 → SFTP 上传 → 临时解压及验证 → 版本切换 → 清理旧版本及上传包 → `remoteGoOn[0]` → `remoteGoOn[1]` → 全部完成并关闭连接。前置任一步骤失败，不执行 `remoteGoOn`。

## 顺序与 shell 行为

复用原有 SSH 连接，为每条配置命令单独打开执行通道，只有当前通道成功关闭且退出码为 `0` 时才启动下一条。标准输出和错误输出会转发到本地。命令前加 `set -e`，普通命令失败会停止该 shell；复杂的条件表达式或管道仍遵循远程 shell 自身的退出码规则，例如普通 shell 管道通常仅反映最后一个进程的状态。

各命令在远程服务器执行，使用 SSH 登录用户及其默认 shell，不在本地执行。不同数组元素的工作目录和环境变量不会共享；需要共享时可在一个元素中写 `cd /path && command` 或合并为一个 shell 脚本。`&`、`nohup`、`docker exec -d` 等后台启动会在任务真正完成前返回，不适合要求等待任务完成的配置。

## 失败与输出

命令启动失败、通道报错、非零退出码或信号终止都会停止后续命令，关闭 SSH 连接，并将 CLI 退出码设为 `1`。错误中标明失败的第几条；不直接打印配置命令正文，命令自身产生的输出仍会打印。通道先报错再关闭时只处理一次，避免错误后继续执行。

远程文件替换成功后输出“部署文件替换完成”，只有所有后续命令成功后才输出最终“部署完成”。`remoteGoOn` 失败不回滚已经完成的文件替换或先前命令的副作用，使用者可根据业务安排补偿命令。

实现只使用 Node.js 14 支持的 API，不增加依赖；不保留测试文件。验证使用模拟 SSH 和虚构命令，不执行配置里的 Docker、删除或复制命令，不连接真实服务器。
